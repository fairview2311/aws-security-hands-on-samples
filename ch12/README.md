# 第12章　GuardDutyで脅威を検出し、EventBridgeで通知する

本の第12章を終えた時点のファイルです。本のコードの枠の上の「サンプルコード　ch12/…」は、このフォルダのファイルを指します。このフォルダには、それまでの章で使ったファイルもすべて入っています。

この章でできるようになること:

- GuardDuty で脅威を検出し、検出結果をメールで受け取れる
- 対応しない検出結果を、抑制ルールでアーカイブできる

第11章の終わりに検証環境を削除したときは、第11章のコードで作り直してから進めます。GuardDuty の検出器は1リージョンに1つだけです。既に検出器があるときは、そのアカウントでは続けず、専用の検証用アカウントを使います。無料期間は、アカウントとリージョンごとに30日間で1回です。

## この章での使い方

コマンドは、Windows は PowerShell、Mac はターミナルで実行します。本では、第1章で作る作業用フォルダ `aws-security-book` のファイルを書き換えながら進みます。このフォルダは書き換えた後の状態なので、自分のファイルとの比較に使います。AWS の料金は読者の負担で、攻撃の手順は自分が管理する AWS アカウントのリソースにだけ実行します（[リポジトリのトップ](../README.md)の「最初に読んでください」）。途中の章から始めるときは、トップの「途中の章から始めるとき」を見てください。

1. 作業用フォルダの `terraform.tfvars` に `alert_email = "test@example.com"` の行を追加し、自分が受け取れるメールアドレスに書き換えます（`terraform.tfvars.example` を参照）。

2. 本の手順で、作業用フォルダのファイルを書き換えて `terraform apply` を実行します。書き換えた結果は、このフォルダのファイルと同じになります。

3. 届いた購読の確認のメールの［Confirm subscription］を押します。押さないと、通知は届きません。

4. 第13章に続けて進むときは、検証環境をこのまま使います。時間を空けるときは `terraform destroy` で削除します。GuardDuty の検出器も削除され、検出結果と設定は元に戻せません。

## うまくいったかの確かめ方

- 本の第3節のとおり、サンプルの検出結果がメールで届く

動作しないときは、本の第12章の「うまくいかないとき」を見てください。
